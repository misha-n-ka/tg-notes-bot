# Roadmap: NotesBot

## Overview

Завершить существующий MVP для личных заметок и практики Python, сохранив
порядок и номера этапов из [docs/roadmap.md](../docs/roadmap.md).
Фаза 1 реализована до инициализации GSD; следующие фазы выполняются
последовательно и только по отдельному поручению пользователя.
Roadmap утверждён пользователем 28 октября 2026 года.

## Phase Details

### Phase 1: Настройки и каркас
**Goal:** Подготовить пакет, настройки окружения и инструменты разработки.
**Depends on:** Нет.
**Requirements:** CONFIG-01
**Success Criteria**:
1. Существуют пакет `notes_bot`, зависимости, настройки Ruff и pytest.
2. `load_settings()` читает обязательный непустой токен и путь к БД из окружения;
   путь по умолчанию — `data/notes.sqlite3`, пустой путь отклоняется.
3. Приложение не загружает `.env` автоматически; токен исключён из `repr` настроек.
**Plans:** 0 GSD plans — реализовано до инициализации GSD.
**Canonical refs:** docs/mvp.md, docs/progress.md, .planning/codebase/STACK.md

Реализация подтверждена статическим чтением. Результаты прежних проверок
за 19 октября 2026 года находятся в `docs/progress.md`; повторных запусков
при инициализации GSD не было. Статус фазы унаследован из существующей сводки,
а не из выполненного GSD-плана или новой верификации.

### Phase 2: Создание и чтение заметок
**Goal:** Создать независимое от Telegram файловое SQLite-хранилище
для сохранения исходного текста и чтения последних 10 записей владельца.
**Depends on:** Phase 1
**Requirements:** NOTE-03
**Success Criteria**:
1. `Storage.initialize()` создаёт каталог и таблицу, повторная инициализация
   и новый экземпляр хранилища сохраняют доступ к ранее записанным заметкам.
2. `add_note()` сохраняет текст без изменений, включая переносы и emoji,
   фиксирует запись и возвращает `Note` с ID, владельцем и временем UTC.
3. `list_notes()` возвращает последние 10 записей только заданного владельца
   в порядке `id DESC`; заметки другого пользователя исключены.
4. SQL использует параметры; соединение открывается и закрывается внутри
   каждой операции, в том числе при ошибке.

**Canonical refs:** docs/plan.md, docs/mvp.md, docs/architecture.md, AGENTS.md

Граница — `notes_bot/storage.py` и `tests/test_storage.py`, без Telegram,

### Phase 3: Первый рабочий сценарий
**Goal:** Получить первый рабочий сценарий: запуск бота, инструкция и сохранение
текста в личном чате с корректными ответами и обработкой ошибок.
**Depends on:** Phase 2
**Requirements:** NOTE-01, NOTE-02, CHAT-01, CHAT-02, INPUT-01, REPLY-01, SAFE-01, SAFE-02, SAFE-03, RUN-01
**Success Criteria**:
1. Точка входа связывает настройки, подготовку БД и обработчики и запускает
   polling; `/start` возвращает приветствие и инструкцию.
2. Текст из личного чата сохраняется без изменений, включая ссылки без загрузки
   страниц, и пользователь получает ID только после успешной записи.
3. В группах бот предлагает личный чат; пустой текст и неизвестные команды
   не сохраняются и сопровождаются подсказкой.
4. Владелец берётся из `from_user.id`, ответы отправляются обычным текстом;
   ошибки хранения не дают ложного успеха, токен и тексты заметок не логируются.
5. SQLite вызывается через `asyncio.to_thread`; обработчики проверены
   без настоящего Telegram API, затем выполнено ревью первого рабочего сценария.
**Plans:** TBD
**Canonical refs:** docs/mvp.md, docs/architecture.md, docs/roadmap.md, AGENTS.md

Изоляция владельцев и защита групп применяются ко всем последующим командам;
в фазе 4 они повторно проверяются на чтении, поиске и удалении.
Сетевой запуск бота требует отдельного разрешения.

### Phase 4: Список, поиск и удаление
**Goal:** Дать пользователю доступ к своим заметкам через `/list`, `/search`
и `/delete`, включая корректные длинные ответы и ошибочные аргументы.
**Depends on:** Phase 3
**Requirements:** LIST-01, SEARCH-01, SEARCH-02, DELETE-01, DELETE-02, INPUT-02, REPLY-02
**Success Criteria**:
1. `/list` показывает последние 10 собственных заметок по `id DESC`.
2. `/search` находит буквальную подстроку через `casefold()`, включая кириллицу,
   `%` и `_`; выдаёт только свои записи по `id DESC` без отдельного лимита.
3. `/delete` принимает положительный целочисленный ID, удаляет только свою запись
   и подтверждает успех после операции; чужая и отсутствующая запись дают
   одинаковое сообщение «Заметка не найдена».
4. Пустые аргументы, неверный ID и неподдерживаемые сообщения дают подсказку;
   длинные ответы делятся с учётом ограничений Telegram и emoji.
5. Для новых команд проверены ограничения владельцем и личным чатом,
   параметризация SQL, обработка ошибок и отсутствие блокировки event loop.

**Success Criteria**:
