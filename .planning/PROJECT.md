# NotesBot

## What This Is

Telegram-бот для собственных текстовых заметок и учебный проект для практики
разработки на Python. Пользователь сохраняет текст в личном чате с ботом,
просматривает последние заметки, ищет и удаляет свои записи.

## Core Value

Быстро сохранить текст в Telegram и позже найти его без потери данных и доступа
к чужим заметкам.

## Requirements

### Validated

Подтверждено статическим чтением существующего кода; проверки в рамках
инициализации GSD не запускались.

- ✓ Каркас Python-пакета и настройки `Settings` / `load_settings()` существуют.
- ✓ Настройки читаются из переменных окружения: обязательный `BOT_TOKEN` и
  `DATABASE_PATH` с путём по умолчанию `data/notes.sqlite3`; пустые значения
  отклоняются, токен исключён из `repr` настроек.

### Active

- [ ] Сохранять исходный текст заметки в файловой SQLite-БД и возвращать её ID
  после успешной записи.
- [ ] Показывать последние 10 собственных заметок от новых к старым.
- [ ] Запускать polling и объяснять команды через `/start`.
- [ ] Искать буквальную подстроку без учёта регистра, включая кириллицу,
  только в собственных заметках; результаты выдавать от новых к старым.
- [ ] Удалять собственную заметку по положительному целочисленному ID;
  одинаково отвечать для чужой и отсутствующей записи.
- [ ] Обрабатывать ошибочные команды, пустой текст и неподдерживаемые сообщения
  с подсказкой; в группах предлагать перейти в личный чат.
- [ ] Отправлять ответы обычным текстом и делить длинные сообщения с учётом emoji.
- [ ] Проверить соответствие MVP, обработку ошибок и изоляцию данных владельцев
  на вымышленных данных без настоящего Telegram API.

### Out of Scope

- LLM и извлечение содержимого ссылок — первый MVP хранит только исходный текст.
- Теги, редактирование и пагинация — исключены из согласованного MVP.
- Веб-интерфейс — взаимодействие ограничено Telegram.
- Работа с заметками в группах — MVP поддерживает только личные чаты.
- Коммерческий сервис и дополнительные функции ради учебных целей — текущее
  поручение ограничено личными заметками и существующими требованиями.

## Context

Проект сочетает практическую задачу личных заметок и обучение разработке
на Python. Учебная цель не расширяет функциональность MVP.

На момент инициализации GSD реализованы каркас пакета, настройки и тесты
настроек; настроены зависимости, Ruff, pytest и хук проверки Python-файлов.

## Constraints

- **Стек:** Python 3.12+, aiogram 3, стандартный `sqlite3`, pytest, uv и Ruff;
  не вводить новые библиотеки или слои ради локальной задачи.
- **Модули:** `storage.py` не зависит от Telegram, `handlers.py` отвечает за
  команды и ответы, `__main__.py` связывает компоненты и запускает polling.
- **Доступ к данным:** владелец определяется через Telegram `from_user.id`;
  чтение, поиск и удаление ограничены его `user_id`, SQL использует параметры.
- **Сохранность:** исходный текст не изменяется; успех записи и удаления
  подтверждается только после успешной операции хранения.
- **Асинхронность:** синхронный SQLite вызывается через `asyncio.to_thread`;
  соединение открывается и закрывается внутри одной операции в рабочем потоке.
- **Поиск:** получить собственные заметки и сравнить строки через `casefold()`;
  этот вариант рассчитан на небольшую личную базу.
- **Секреты:** приложение не загружает `.env` автоматически; агенту запрещено
  читать этот файл. Токен, тексты реальных заметок и БД не попадают в логи
  или отслеживаемые файлы.
- **Проверки:** использовать вымышленные данные, временные файловые SQLite-БД
  и проверки обработчиков без настоящего Telegram API. Применять правила
  проверок из `AGENTS.md`; результаты прежних запусков не выдавать за текущие.
- **Порядок работы:** реализация этапов, Git-операции, установка зависимостей
  и сетевой запуск требуют соответствующего отдельного поручения пользователя.

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Личные заметки и учебный проект | Обе цели подтверждены пользователем | Принято |

| Отделить реализованный каркас от будущих функций | Документация целевой архитектуры не означает готовность бота | Принято |
| Сохранить пять этапов существующего roadmap | Пользователь выбрал прежний порядок вместо вертикальных срезов | Принято |
