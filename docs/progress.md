Есть каркас пакета, `Settings` / `load_settings()` и тесты настроек.
Проверяются обязательный токен, непустой путь БД и отсутствие токена в `repr`.
Проверка ошибки токена требует полного ключа `BOT_TOKEN` через `\bBOT_TOKEN\b`.
Хранилище, Telegram-обработчики и точка входа бота пока отсутствуют.

Настроены зависимости и инструменты в `pyproject.toml` и `uv.lock`, правила
агента, два локальных навыка, хук Ruff и профиль разрешений `notes-bot`
с файловым `deny` для корневого `.env`. Локальный `.env` исключён из Git;
устаревшие упоминания шаблона настроек удалены.

Описание проекта и скриншоты проверок — в [about.md](about.md), порядок работы
агента и границы защитных механизмов — в [agent-workflow.md](agent-workflow.md).

## Текущее поручение и границы

27 октября 2026 года добавлено демонстрационное правило в
`.codex/rules/notes-bot.rules`: команда `cat private/demo.txt` запрещена,
а `cat public/demo.txt` не совпадает с правилом. Созданы оба файла с вымышленным
текстом. Два запуска `codex execpolicy check --pretty --rules
.codex/rules/notes-bot.rules -- cat <путь>` завершились с кодом 0: для закрытого
пути получено `decision: forbidden`, для публичного — `matchedRules: []`.
Целевые команды `cat` не выполнялись. CLI предупредил о невозможности создать
PATH aliases в sandbox; проверке правил это не помешало. Правило сравнивает
точный аргумент команды, не является файловым запретом и не покрывает другие
способы чтения. Для загрузки правила нужен перезапуск Codex с доверенным
проектным слоем `.codex/`. Проверены diff и новые файлы; тесты и сборка не
запускались, код приложения не менялся. Staging сохранён.

Предыдущее поручение — устранить ограничения и закрыть открытые вопросы текущего
этапа. Существующая пользовательская правка этого файла сохранена. Пользователь
явно разрешил компиляцию, весь набор тестов, сборку и необходимые установки;
установка не потребовалась. Staging не менялся.

Найден уже установленный `.tools/uv/bin/uv` и build backend `uv_build 0.13.1`.
В README добавлена команда сборки с локальным uv и кэшем. В настройках pytest
корневой `.env` исключён из обхода через `--ignore=.env`: без этого pytest
падал при проверке типа запрещённого файла. Доступ к `.env` не ослаблен,
его содержимое не читалось. Повторный запуск всех 14 тестов прошёл.

Ближайший этап — пункт 2 [roadmap](roadmap.md). Его реализация не поручена;
наличие плана не разрешает начинать её автоматически. Постоянные правила
и разрешения определены в [AGENTS.md](../AGENTS.md). Прежнее разрешение установки
инструментов для пункта 1 не распространяется на следующие этапы.

## Решения и оставшиеся ограничения

- Сборка подтверждена; при отсутствии uv в PATH использовать локальную команду
  из таблицы. uv предупреждает о кэше внутри проекта; проверка состава обоих
  архивов подтвердила, что кэш в них не попал.
- Пользователь подтвердил, что хук доверенный и включён. Автоматический запуск
  проверен в текущем чате на временном Python-файле; ручное форматирование
  между созданием и чтением файла не запускалось. В новых средах и после
  изменения определения хука доверие проверять через `/hooks`.
- В текущем чате активная политика явно содержит неэскалируемый запрет `.env`
  для обоих workspace roots. Отказ pytest при проверке типа файла также
  подтвердил действие запрета. Перезапуск ради защиты этого чата не требуется;
  имя выбранного профиля по одной эффективной политике не определяется.
  Для новых чатов сохраняются инструкции активации в agent-workflow.
- Тесты проверяют существующие настройки и скрипт хука. Отсутствие
  проверок будущих функций — граница этапа, а не дефект текущего набора тестов.
  Новые функции проверять при реализации соответствующих пунктов roadmap;
  настоящий Telegram API — отдельно после разрешения пользователя.

Открытых вопросов, блокирующих работу над текущим каркасом, не осталось.

пропущенные проверки и открытые вопросы. Порядок этапов хранить в roadmap,
шаги выбранного этапа — в plan; подробную историю изменений сохраняет Git.
