# NotesBot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Делегирование возможно только при выборе пользователем работы с субагентами; тогда использовать superpowers:subagent-driven-development.

**Goal:** Создать Telegram-бота для сохранения, просмотра, поиска и удаления собственных текстовых заметок.

**Architecture:** Обработчики Telegram вызывают самостоятельное SQLite-хранилище. Точка входа загружает настройки, инициализирует БД и запускает polling. Отдельный сервисный слой не нужен.

**Tech Stack:** Python 3.12+, aiogram 3, sqlite3, pytest, uv, Ruff.

**Spec:** [mvp.md](mvp.md), схема — [architecture.md](architecture.md).

## Global Constraints

- Реализовать только возможности и ограничения из `mvp.md`.
- Любое чтение, поиск и удаление ограничивать `user_id` отправителя.
- Операции SQLite выполнять в рабочем потоке с отдельным соединением на операцию.
- Существующий staging сохранить; коммиты и push не выполнять без отдельного поручения.
- После изменений кода выполнять проверку компиляции, весь набор тестов и сборку по `AGENTS.md`: пользователь разрешил эти проверки. Команды отдельных тестов ниже служат для промежуточной проверки. Установка зависимостей и приложения требует отдельного разрешения; при отсутствии инструментов или окружения сообщить о невыполненных проверках.
- Перед выбором точных версий зависимостей и деталей aiogram сверить официальную документацию. Не обновлять зависимости, не связанные с задачей.

## Review Focus

- Запрос или удаление чужой заметки: данные не выдаются, запись не меняется — задача 2.
- Русский текст, `%`, `_` и кавычки в поиске: буквальный поиск без учёта регистра — задача 4.
- Группы, неизвестные команды и сообщения без отправителя: заметки не сохраняются и не выдаются — задача 3.
- Длинные заметки с emoji и символами разметки: исходный текст сохранён, ответы допустимы для Telegram — задачи 3 и 4.
- Ошибка БД или повторный запуск: нет ложного успеха, сохранённые данные остаются доступными — задачи 2 и 3.

## Задача 4: Список, поиск и удаление

**Обновить:** `notes_bot/storage.py`, `notes_bot/handlers.py`, `tests/test_storage.py`, `tests/test_handlers.py`, `README.md`.

**Интерфейсы:** добавить `Storage.search_notes(user_id: int, query: str) -> list[Note]` и `Storage.delete_note(user_id: int, note_id: int) -> bool`; `create_router()` сохраняет прежнюю сигнатуру.

- [ ] Добавить тесты хранилища: `test_search_cyrillic_casefold` на «Compose и КОТ» с запросом «кот»; `test_search_literal_symbols` на `%`, `_` и кавычки; `test_search_only_owner`; `test_delete_only_owner`; `test_delete_missing_returns_false`. После попытки чужого удаления исходная запись остаётся доступной владельцу.
- [ ] Реализовать поиск через `casefold()` по собственным заметкам, в порядке `id DESC`; удаление — параметризованным запросом по `id` и `user_id`, результат определяется количеством удалённых строк.
- [ ] Добавить проверки обработчиков: `/list` с пустым и непустым результатом; `/search` с пустым запросом и без совпадений; `/delete` без ID, с `abc`, `0`, `-1`, несколькими аргументами, чужим ID и собственным ID. Чужой и отсутствующий ID дают одинаковый ответ.
- [ ] Реализовать команды перед общим обработчиком текста. Для `/search` взять весь остаток сообщения как запрос, убрав только внешние пробелы; `/delete` требует ровно один ID.
- [ ] В `handlers.py` добавить `split_response(text: str) -> list[str]`, при необходимости для результатов команд. Каждый фрагмент — максимум 4096 кодовых единиц UTF-16, без разделения Unicode-символа. Добавить `test_split_response_preserves_text` и `test_split_response_emoji_limit`: объединение фрагментов равно исходному тексту, каждый фрагмент укладывается в лимит. Лимит перед реализацией сверить по официальной документации Telegram.
- [ ] Выводить ID и текст заметок обычным текстом, делить длинные ответы, дополнить инструкцию `/start` и README.
- [ ] При разрешённых условиях выполнить `pytest tests/test_storage.py tests/test_handlers.py -q`; ожидается успешное завершение без сетевых вызовов.
