# NotesBot: требования MVP

Бот позволяет сохранять, просматривать, искать и удалять текстовые заметки. На первом этапе бот не использует LLM.

## Возможности

- `/start`: приветствие и инструкция по командам.
- Обычное текстовое сообщение: сохранить исходный текст как заметку и вернуть её ID. Ссылки хранятся как текст, без загрузки страниц.
- `/list`: последние 10 собственных заметок, от новых к старым.
- `/search <query>`: поиск буквальной подстроки без учёта регистра, включая кириллицу, только в собственных заметках. Результаты — от новых к старым; отдельного лимита поиска в MVP нет.
- `/delete <id>`: удаление собственной заметки по положительному целочисленному ID.
- Чужая и отсутствующая заметки дают одинаковый ответ: «Заметка не найдена».

## Ограничения

- Python 3.12+, aiogram 3, SQLite, pytest, uv, Ruff.
- Личные чаты; в группах не сохранять и не выдавать заметки, предложить открыть личный чат.
- Владелец определяется по Telegram `from_user.id`, а не по аргументам команды.
- Неизвестные команды не сохранять; пустые аргументы, неверный ID и неподдерживаемые сообщения сопровождать подсказкой.
- Исходный текст сохранять без изменения; пустой или состоящий из пробелов текст не сохранять.
- Ответы отправлять как обычный текст без HTML/Markdown. Длинные ответы делить на сообщения, соблюдая ограничения Telegram, в том числе для emoji.
- При ошибке хранения не сообщать об успехе. Не записывать токен или текст заметок в логи.
- Не добавлять теги, редактирование, пагинацию, веб-интерфейс, извлечение содержимого ссылок или интеграцию LLM.

## Архитектура

Схема модулей: [architecture.md](architecture.md).

`__main__.py` связывает настройки, хранилище и обработчики и запускает polling. `handlers.py` отвечает за Telegram; `storage.py` не зависит от Telegram.

SQLite используется через стандартный `sqlite3`. Синхронные операции хранилища вызываются из обработчиков через `asyncio.to_thread`; соединение открывается и закрывается внутри каждой операции в рабочем потоке. База должна быть файловой, включая временные базы в тестах.

Таблица `notes`: `id INTEGER PRIMARY KEY`, `user_id INTEGER NOT NULL`, `text TEXT NOT NULL`, `created_at TEXT NOT NULL` (UTC). Чтение, поиск и удаление ограничиваются владельцем. Запросы используют SQL-параметры. Последние записи сортируются по `id DESC`.

Для поиска сначала получить собственные заметки, затем сравнить `query.casefold()` с `text.casefold()`. Это простой вариант для небольшой базы; при росте объёма потребуется пересмотреть поиск.

Настройки: `BOT_TOKEN` (обязателен), `DATABASE_PATH` (по умолчанию `data/notes.sqlite3`). Секреты задаются переменными окружения; `.env.example` содержит только заглушки и сам по себе не загружается приложением.

## Правила выполнения

Не менять staging, не создавать коммиты и не отправлять изменения без отдельного поручения. После изменений кода, тестов, зависимостей или конфигурации сборки обязательны проверка компиляции, весь набор тестов и сборка пакета; пользователь разрешил эти проверки без дополнительного согласования. Команды и исключения для изменений только документации определены в `AGENTS.md`. Установку зависимостей, установку приложения и запуск бота с обращением к Telegram согласовать отдельно.
