# План: создание и чтение заметок

Пункт 2 из [roadmap](roadmap.md). План подготовлен для следующего этапа;
его наличие не разрешает начинать реализацию. Текущее состояние и границы
поручения, текущая и следующая задачи указаны в [progress](progress.md).
Этот файл содержит только результат, границы и шаги выбранного этапа.

## Результат и границы

Самостоятельное SQLite-хранилище умеет создавать заметки и возвращать последние
10 записей владельца. Telegram-обработчики, поиск и удаление относятся к другим
пунктам roadmap и в этот план не входят.

Требования: [mvp.md](mvp.md); схема: [architecture.md](architecture.md).
Постоянные правила и обязательные проверки: [AGENTS.md](../AGENTS.md).

## Шаги реализации

**Создать:** `notes_bot/storage.py`, `tests/test_storage.py`.

**Интерфейсы:** `Note` — dataclass с `id: int`, `user_id: int`, `text: str`, `created_at: str`; `Storage(database_path: Path)` с синхронными методами `initialize() -> None`, `add_note(user_id: int, text: str) -> Note`, `list_notes(user_id: int, limit: int = 10) -> list[Note]`.

- Добавить тесты: `test_add_preserves_text` сравнивает текст с исходным, включая переносы и emoji; `test_list_latest_ten` создаёт 12 записей и ожидает последние 10 в обратном порядке; `test_list_only_owner` исключает записи другого владельца.
- Добавить `test_reinitialize_preserves_notes`: повторная инициализация и новый экземпляр `Storage` с тем же файлом сохраняют доступ к заметке. Каждая проверка использует отдельный файл в `tmp_path`.
- Реализовать таблицу из спецификации, создание родительского каталога и указанные методы. Запись фиксировать до возврата результата; соединение закрывать при успехе и ошибке.
- При разрешённых условиях выполнить `pytest tests/test_storage.py -q`; ожидается успешное завершение. Просмотреть SQL на наличие параметров и ограничения владельцем.

итоговый diff и обновить `progress.md`: результат, фактически выполненные проверки
и оставшиеся ограничения. Не менять staging и не создавать коммит без поручения.
