# Проверка правил команд NotesBot

Прочитать корневой `AGENTS.md` и выбранный файл `.rules`. По умолчанию проверять
`.codex/rules/notes-bot.rules`; пути считать от корня репозитория.
Навык выполняет проверку без исправлений, если пользователь не поручил изменения.

Использовать установленный `codex execpolicy check`. Проверить доступные опции
через `codex execpolicy check --help`, если синтаксис установленной версии
неизвестен. Если CLI отсутствует, сообщить об этом и ограничиться анализом текста;
не устанавливать инструменты автоматически.

Для каждого проверяемого ограничения выбрать команду, которая должна совпасть,
и близкую команду, которая совпадать не должна. Для ограничения по пути сохранить
команду и флаги, меняя только путь. Учитывать встроенные `match` и `not_match`.
Передавать примеры как аргументы после `--`, например:

```sh
codex execpolicy check --pretty --rules .codex/rules/notes-bot.rules -- cat private/demo.txt
codex execpolicy check --pretty --rules .codex/rules/notes-bot.rules -- cat public/demo.txt
```

Целевые команды не выполнять: не читать проверяемые файлы, не запускать бота,
не удалять данные и не менять Git ради проверки. Проверки политики не требуют
реальных секретов или заметок; использовать вымышленные пути и аргументы.

Сравнить `matchedRules` и `decision` с ожидаемым результатом. Пустой
`matchedRules` означает отсутствие совпадения в проверенном наборе правил,
а не разрешение команды всеми активными политиками. При нескольких совпадениях
учесть наиболее строгое решение: `forbidden`, затем `prompt`, затем `allow`.

В отчёте показать команды, ожидания, фактические результаты и расхождения.
Отдельно назвать непокрытые варианты аргументов, если они существенны для запроса:
`./`, абсолютный путь, другой порядок опций или shell-обёртка. Не представлять
точный префикс как файловый запрет для всех инструментов и не утверждать, что
проверка отдельного файла подтверждает загрузку правил в текущей сессии.
