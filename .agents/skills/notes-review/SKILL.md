# Ревью изменения NotesBot

Прочитать `AGENTS.md` и `docs/mvp.md` от корня Git-репозитория. Определить предмет ревью по запросу: рабочее дерево, commit или переданный фрагмент. Проверить staged, unstaged и новые файлы при ревью текущих изменений; не менять staging. Если код ещё не создан, сообщить, что доступно только ревью документов.

Прочитать связанный код и непосредственных потребителей, а не только diff. Для доступа к данным проследить путь от Telegram-отправителя до SQL; для ответа — от результата хранения до подтверждения пользователю. Проверить применимые Code Review Rules из `AGENTS.md` и тесты затронутого поведения.

Каждое замечание должно описывать конкретный дефект: приоритет, место, вход или условие воспроизведения, последствие для пользователя и минимальное исправление. Использовать проверенные пути и строки. Если дано только словесное описание, обозначить выводы как основанные на описании и не придумывать строки или содержимое файлов.

Пример: удаление только по `id` позволяет удалить чужую заметку; безопасный запрос ограничивает и `id`, и `user_id`, полученный от отправителя. Тест должен показать, что попытка пользователя А не меняет запись пользователя Б.

Вывести замечания в порядке серьёзности, затем статус проверок и открытые вопросы. Если дефектов не найдено, написать это прямо и отдельно указать пределы проверки. Не выдавать отсутствие тестов или запусков за подтверждение работоспособности.

Выполнять только разрешённые проверки без установки и запрещённой сборки. По умолчанию ничего не исправлять, не запускать настоящего бота, не создавать commit и не отправлять изменения. Навык сам по себе не разрешает эти действия.
